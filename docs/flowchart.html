校园失物招领 · 系统数据流图

数据存储于浏览器 localStorage，无后端服务器；状态变更后各页面统一从数据层重渲染，保证结果同步

用户
失主 / 拾获者
▼
视图层 View
首页 · 发布 · 搜索 · 详情 · 我的发布
（index.html + style.css）
▼
交互层 Controller
app.js：hash 路由、事件绑定、渲染
▼
业务逻辑层 Model
core.js：表单校验 / 关键词搜索 / 分类筛选 / 状态标记 / 统计（纯函数）
▼
数据层 Storage
data.js：示例数据 seed + localStorage 读写持久化

核心业务流程

流程一 发布信息（失主 / 拾获者共用）
点击底部「＋」
→
选择 寻物 / 招领
→
填写名称·地点·时间·联系方式·照片（选填）
→
表单校验
→
通过？
→
存入 localStorage
→
发布成功弹窗
→
「我的发布」可查看
校验不通过时，逐字段显示红色错误提示并 toast 提醒；必填项：类型、名称、地点、时间、联系方式。
流程二 浏览与搜索（失主视角）
进入首页
→
全部 / 寻物 / 招领 Tab
→
搜索框输入关键词 / 热门标签 / 分类筛选
→
core.searchItems 过滤
→
有结果？
→
列表展示 + 结果计数
→
点击卡片 → 详情页
→
复制微信号联系
无结果时显示「没有找到相关信息，换个关键词试试吧」；已解决的信息在列表中置灰并标注「已找回 / 已归还」。
流程三 更新信息状态（发布者）
「我的发布」选中记录
→
点击「标记已找回 / 已归还」
→
确认框
→
core.markResolved 更新状态
→
写入 localStorage
→
首页 / 搜索 / 详情同步显示「已找回 / 已归还」
状态标记为幂等操作（重复标记不产生变更）；纯函数返回新数组，不修改原数据，便于单元测试与回归。
